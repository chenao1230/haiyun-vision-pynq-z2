# 海云智视 FPGA 自主选题参赛工程

平台：PYNQ-Z2，XC7Z020-1CLG400C。PL 执行 YOLOv4-Tiny 计算，ARM 执行调度、后处理、ByteTrack 与以太网通信；电脑运行上位机、告警及单目深度预测。

## 先看这些入口
- 使用：`start_pc.cmd`，或 `python src/vitis/pc_app/app.py`。
- 当前上板文件：`board/BOOT.bin`；完整演示启动分区内容：`board/sd_card/`。
- Vivado 工程：`src/vivado/hardware/project/haiyun_pynq_z2.xpr`。
- Vivado 重建入口：`build/recreate_vivado.cmd`。
- 当前 Vitis/ARM 应用：`src/vitis/firmware/app/src/`，Makefile 位于其上级。
- 当前 BSP 与 FSBL：`src/vitis/build/official_generated_fast2/`、`src/vitis/build/official_generated/`。
- 设计报告：[设计报告.pdf](report/设计报告.pdf)。
- 技能包使用说明：[skill/README.md](skill/README.md)；上位机按下文顺序操作。

## 上位机操作说明（按顺序执行）

常用操作顺序：**启动上位机 → 连接板卡并等待 READY → 选择数据来源 → 选择照片组 → 选择处理模式 → 查看首帧并按需画框 → 点击一次“开始运行” → 等待结束 → 回放或导出。**

当前界面已移除场景“停止”按钮、“选择任意图片（独立检测）”按钮和场景下拉菜单中的跟踪合集。连续运行场景1至7使用独立的“运行场景1-7追踪”按钮。

### 1. 首次准备与启动

1. 将完整项目放在纯英文路径，例如本机的 `D:\haiyun_fpga_submission\haiyun_fpga_submission`。保持目录结构；中文路径可能导致 OpenCV 无法读写单目测距图片。
2. 首次准备板卡时，先断电，将 `board/sd_card/` 中的内容复制到 FAT32 SD 启动分区根目录；插回板卡，选择 SD 启动，再上电。已经准备好的 SD 卡无需每次重复制。
3. 用网线连接电脑与板卡，将电脑有线 IPv4 设置为 `192.168.1.20`，子网掩码为 `255.255.255.0`。板卡地址为 `192.168.1.10`，端口为 `5000`。
4. 双击项目根目录的 `start_pc.cmd`。只保留一个上位机窗口；更新程序后需关闭旧窗口，再重新启动。
5. 本机启动脚本会优先使用 `SHIP_PYTHON` 指定的解释器；未设置时尝试已有的 `C:\Users\liudanian\miniconda3\envs\haiyun-repro\python.exe`，否则使用系统 `python`。换电脑时使用带 Tk 的 Python，执行 `python -m pip install -r requirements.txt` 安装依赖，再启动。
6. 单目模型源码在 `src/depth_anything_v2/metric_depth/`，权重在 `data/models/depth_best.pth`，随包提供。不要只复制 `app.py`。

### 2. 连接并确认板卡就绪

1. 确认上方 IP 为 `192.168.1.10`、端口为 `5000`，点击“连接”。
2. 等待状态显示“板卡已就绪”或 `READY`。“连接”变成“断开”仅表示连接已建立，仍需等待板卡完成初始化。
3. 只有板卡就绪后才能执行检测、跟踪或摄像头推理。电脑数据模式也需要板卡，不能仅靠加载图片完成检测。

### 3. 选择数据来源

选择以下一种来源，然后再选择照片组和处理模式。

| 数据来源 | 操作 | 读取位置与用途 |
|---|---|---|
| 电脑照片组 | 点击“加载电脑数据” | 原图：`data/pc_files/images/`；清单：`data/pc_files/manifest.csv`。图片由电脑发送到板卡处理。 |
| SD 卡场景 | 点击“使用SD卡场景” | 板卡读取 SD 卡输入；电脑使用 `src/vitis/data/manifest.csv` 和 `src/vitis/data/images/` 匹配并显示结果。电脑清单需与板卡 SD 清单 CRC 一致。 |

电脑数据集默认使用包内 `data/pc_files/`。默认位置缺少 `manifest.csv` 或 `images/` 时，程序会弹出目录选择框；应选择同时包含这两项的父目录。清单的 `source_image` 字段必须对应原图文件名。

### 4. 选择照片组，再选择模式

1. 在“场景”下拉菜单选择要运行的单独照片组，例如“跟踪01—日光单船（G066）”。
2. **先选照片组，再选处理模式。** 当前程序切换照片组时会将模式设回“检测＋跟踪”，因此需要“仅检测”或“检测＋跟踪＋测距”时，应在选择照片组之后设置。
3. 根据数据选择模式：

| 模式 | 适用情况 |
|---|---|
| 仅检测 | 独立图片或只需检测船框。检测01等不连续图片组以及“ALL（全部，仅检测）”应使用此模式。 |
| 检测＋跟踪 | 跟踪01至跟踪07等连续照片组，显示船框、目标 ID 和轨迹。 |
| 检测＋跟踪＋测距 | 连续照片组，在板卡检测与跟踪的基础上由电脑计算单目估距。显示的 `~距离` 为估计值。 |

### 5. 首帧预览与画矩形

1. 选择照片组和“检测＋跟踪”或“检测＋跟踪＋测距”后，程序会自动显示该组第一帧，并等待操作，**不需要先点“开始运行”来获取首帧**。
2. 此时显示的是原图预览，还没有执行本次板卡推理；没有检测框、ID 或距离是正常的。
3. 需要区域预警时，勾选“预警”，点击“画矩形区”，在左侧原图内按住鼠标左键拖出矩形，松开即保存。深度图并排显示时，应在左侧原图上画。
4. 需要第二个矩形时，再点一次“画矩形区”后拖拽；同组可以保留多个矩形。需要越线规则时点击“画越线”，从 A 拖到 B，松开保存；方向可在“更多设置”中调整。
5. 按 `Esc` 取消尚未完成的绘制。“清除本组”会清除当前照片组的区域和越线规则；重新画框可重新启用该组规则。其他照片组的规则不受影响。
6. 规则按照片组保存在 `src/vitis/configs/`，再次打开程序时会加载。运行前检查已有区域是否仍适合当前图片；需要更换时先“清除本组”，再画新框。
7. 画好后点击一次“开始运行”。不需要预警框时，也可以直接点击一次“开始运行”。

### 6. 等待本组完成，再切换操作

1. 运行后，上位机会依次处理当前照片组，并显示板卡返回的结果。
2. **运行过程中不要切换照片组、模式、数据来源、清单或原图目录，也不要绘制规则、打开回放或启动另一个任务。** 等待状态显示“本次运行结束”后再操作。
3. 当前没有场景“停止”按钮；普通照片组按组运行到结束。要重跑同组，重新选择该照片组、确认模式，在自动显示的首帧上检查规则，再点“开始运行”。新任务从头运行，不会从上次某一帧续跑。
4. 使用测距时，板卡结果可能先显示，电脑端的测距与预警分析随后完成。导出前等待后台分析完成。
5. 如必须中断，点击“断开”会中断通信；这不是暂停，也不能原位置继续。重新连接后，需等待遗留会话恢复、板卡重新就绪，再开始新的任务。

### 7. 连续运行场景1至7（单独入口）

1. 等待当前任务结束，并确认板卡为 `READY`。
2. 如需预警，先在“使用SD卡场景”下逐个选择跟踪01至跟踪07，在各组首帧上画好所需区域；不需要预警可跳过此步。
3. 点击“运行场景1-7追踪”。该按钮会直接启动七个场景的连续跟踪，**不用再点“开始运行”**。
4. 该入口固定使用 **SD 卡场景和“检测＋跟踪”模式**；当前即使选择的是电脑数据，也会切换到 SD 卡场景。它不使用电脑上传模式，也不沿用“检测＋跟踪＋测距”。
5. 每个场景独立运行并重置跟踪状态，合集保留顺序结果。等待所有场景结束后再回放或导出。下拉菜单无需额外的“跟踪合集”项。

### 8. 回放与导出

1. 本组或合集运行结束后，用“上一帧”“下一帧”、底部滑块或“播放/暂停”查看结果。“播放速度”只影响回放速度。
2. 单击右侧警示记录可跳转查看对应帧。需要修改规则时，在任务结束后编辑；修改后的规则可对已有结果重新分析。
3. 点击“导出视频”，选择输出文件夹。若提示后台分析中，等待测距和预警分析完成后再导出。
4. 以后需要回放，点击“打开结果”，选择 `src/vitis/runs/<运行编号>/frames.jsonl`；合集结果位于 `src/vitis/runs/COLLECTION_<编号>/frames.jsonl`。包内既有结果也可从 `board/results/` 中选择相应结果文件。回放需要保留匹配的原图。
5. “看演示”依赖原历史数据是否存在。本包的常规离线回放请使用“打开结果”，不要依赖该历史入口。

### 9. 摄像头流程（与照片组分开运行）

1. 确认照片组或合集任务已结束，板卡为 `READY`。
2. 选择设备编号，点击“打开摄像头”，等待左侧出现有效实时画面。
3. 选择处理模式，再点“开始摄像头运行”；不要使用照片组的“开始运行”按钮。右侧显示板卡返回的检测或跟踪结果。
4. “暂停/继续”只控制摄像头会话，暂停时保留跟踪状态；需要重新分配跟踪 ID 时使用“重置追踪”。
5. 摄像头开始后，其运行按钮会变为“停止摄像头运行”。使用该按钮结束会话，或点击“关闭摄像头”；等待板卡恢复就绪后再运行照片组。

### 10. 常见状态与处理

| 现象 | 操作 |
|---|---|
| “开始运行”灰色 | 检查网线、电脑 IP、板卡上电与 SD 启动状态；连接后等待 `READY`。 |
| 有首帧，但没有船框 | 首帧是绘制规则用的预览；画框后或不画框时，点击“开始运行”才会推理。 |
| 画不了矩形或设置无反应 | 确认已有首帧、当前任务已结束；先点“画矩形区”，再在原图内部拖拽，不能只单击。 |
| 清单 CRC 不一致 | 使用配套的电脑 SD 清单和板卡 SD 内容；不要在运行中从“更多设置”随意切换输入数据包。 |
| 单目测距不可用 | 确认完整项目位于英文路径，使用含 torch/torchvision 的 Python 环境，模型源码、权重和当前帧原图均存在。 |
| 更新后仍看到旧按钮 | 关闭旧上位机窗口，从本目录 `start_pc.cmd` 重新启动。 |

“更多设置”中的输入数据包、其他清单和原图目录属于手动配置入口。常规操作使用“加载电脑数据”或“使用SD卡场景”；手动配置前先结束任务，并保证清单与原图成套匹配。

## 工具链与复现说明

工具链沿用实际工程的 Vivado/Vitis 2019.2。使用该版本是为了保持现有工程、HLS IP、BSP 与已验证启动产物的兼容组合。新路径下完成了文件与依赖检查；完整重综合、重新训练、全量上板验证的状态见检查表。

SD 默认清单与上位机统一为91帧；历史117帧清单归档在 data/manifest_extended_117.csv，额外输入文件保留。91帧电脑图像与SD输入的量化一致性记录见 sim/dataset_alignment.json。
