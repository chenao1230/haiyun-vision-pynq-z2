# 船舶工程适配示例（可选）

这是本 Skill 方法的来源示例，不是所有工程的固定配置。主结构为 PC 上位机、ARM 裸机 C/C++、HLS 加速器，SD 启动；通信存在串口版本和以太网版本，应查当前版本。

1. 模型：核对实际 YOLOv4-Tiny 层结构、检测头通道、anchors/masks、BN 折叠、权重排列、输入 RGB/CHW、uint8/浮点转换和定点比例。已有 PC 基线用于冻结对照；本 Skill 不声称实现了通用 YOLO 转换器。
2. ARM：负责输入管理、控制加速器、解码/NMS、ByteTrack、通信。实际卷积/池化/上采样划分从代码确认。单改跟踪/NMS 不自动要求修改 PL。
3. 跟踪：冻结相同检测缓存，编译实际 C++ 跟踪代码，按序喂帧、组间重置。分别比较 ID、匹配检测索引、内部滤波框、当前显示框；使用当前匹配检测框显示，不能当成内部滤波器已修复。
4. 指标：有人工身份标注才统计 IDSW/IDF1/MOTA 等，保留标注规模、稀疏帧、开发集复用和漏标限制。没有 GT 时只报告人工观察案例，不能扩增虚构标注。
5. 预警：图像矩形区/越线属于 PC 图像规则，不等同于物理距离/碰撞预警；点云或单目深度另列验证条件。

## 来源于独立复现的历史教训

- 单 tile 数值正确仍可能多执行一次循环并写出逻辑输出区；加入保护区检查，不只比较有效输出。
- 新测试变量与头文件宏冲突属于测试工具错误，应和 DUT 缺陷分开记录。
- 共享写出逻辑不一定减少综合资源；以同配置报告判断，不把代码更短写成资源优化。
- BSP 相对路径、FSBL 的完整 PS 初始化以及 BOOT 中旧 bit 引用都可能造成“源码已改、实际产物没变”。

这些是此前工程复现经验。本次技能包重写没有重新执行该硬件实验；历史 8 项/69,121 输出等阶段性数字不充当本次测试结果，也不概括后续整个复现工程的最终范围。
