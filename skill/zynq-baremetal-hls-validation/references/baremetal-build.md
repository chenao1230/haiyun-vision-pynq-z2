# 裸机构建、平台与 BOOT

## 工程盘点

查找 .project/.cproject、Makefile、build.cmd/Tcl、链接脚本、BSP 的 include/lib、xparameters.h、xsa/hdf、PS 初始化文件、FSBL、BIF 和 bit。记录工具版本与目标 ABI。不能仅凭目录名判断新旧版本，也不把 Eclipse 导入成功当作编译成功。

导入后只有空项目时，先检查真实工程位置、源文件是否存在及是否链接到外部路径，再检查工程类型和视图。不要反复复制不匹配的 BSP 或通过新建空工程掩盖缺失依赖。

## 编译分层

1. 工具无法启动：先验证实际可执行文件、版本和运行环境；不要先改算法。
2. 缺头文件/库：从实际 cwd 解析相对路径；include、lib、处理器和 BSP 配置配套，避免只补单个头文件。
3. 编译/链接：核对 C/C++ 编译器、浮点 ABI、链接脚本、堆栈、DDR 区域和 BSP 库。生成物使用新输出目录，避免旧对象掩盖问题。
4. 核对实际命令、内部错误、退出码、ELF 是否非空和生成时间。保留旧日志。重新链接应用不意味着 BSP 也重新生成。

## PS 平台与硬件接口

核对完整 PS 配置：CPU/FCLK/DDR、UART、SD、GEM、MIO、复位和 AXI 地址映射。配置来源可以是同源平台导出、初始化源码或已解析 FSBL；静态配置证据不冒充实板寄存器读数。

新 IP 集成需检查控制寄存器定义、基址、总线连接、时钟域和复位。如果寄存器布局或地址发生变化，重新导出硬件平台并同步 BSP/驱动；不只替换一个 bit。

## BOOT 来源链

逐项列 BIF 中的 FSBL、bit 和应用 ELF，记录实际解析路径与 SHA256。相对路径按本次 Bootgen 的 cwd 解析；不要默认相对 BIF 目录。可把输入和 BIF 放同一独立打包目录，并在那里执行工程匹配版本的 Bootgen。

FSBL 初始化必须与硬件平台相容。仅 ARM 修改可复用经核对的硬件；硬件修改则需绑定本次实现 bit。BOOT.bin 字节相同只说明文件相同，不能证明它引用了预期源代码。

输出分为“封装成功候选”和“实板验证版本”。实板验证记录启动日志、固件标识、输入清单/CRC、处理帧数、错误状态及结果；没有实际板卡测试时停在候选状态。
