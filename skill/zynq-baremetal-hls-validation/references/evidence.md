# 验证证据、报告与性能

## 工具范围

|脚本|输入/输出|失败与边界|
|check_files.py|参考、候选文件→SHA256 JSON|0 相同；1 不同或候选缺失；2 参数错误。仅字节一致，不证明功能|
|compare_values.py|非空有限数值 JSON 数组、atol/rtol→误差统计|0 通过；1 超差/长度不同；2 非法输入。先统一布局、单位和缩放|
|export_reports.tcl|routed DCP、新/空目录→资源/时序/时钟/路由/功耗估计报告|需要兼容 Vivado；不执行实现，不下载板卡|
|summarize_reports.py|上述英文报告→汇总 JSON|0 所需字段完整且 setup/hold/脉宽裕量非负；1 负裕量；2 缺字段/参数错误|

解析器输出 timing_met 只判断所提取的三类裕量，不等于完整签核。仍需人工/智能体阅读原始报告的未约束路径、约束完整性、DRC、路由状态和黑盒警告。功耗是 Vivado 估算，不是仪表测量。

## 可比较性

资源对照固定器件、工具版本、时钟约束、参数和实现阶段。HLS LUT 估算、独立 IP、顶层综合黑盒及全系统 route 资源不能混成一张“优化前后”表。

耗时分别列采集/预处理、上传、板端读入、PL 计算、解码/NMS、跟踪、返回、PC 绘制。记录计时点、计数器频率、样本数、冷启动与稳态，至少平均值，必要时中位数/高分位。吞吐与单帧延迟分开；并行阶段不机械相加。离线视频回放 FPS 不等于板端推理 FPS。

PC 与板卡对照记录 CPU/GPU、输入尺寸、精度、batch 和是否包含传输。资源/功耗优势需要实测或报告支撑，不能从“FPGA”名称推出更快或更节能。

## 结论等级

已执行通过、已执行失败、未执行、继承历史证据分别记录。本包 examples/project_reports 是旧包保留的历史真实工程报告，只用于解析回归；其 LUT/DSP/时钟/功耗不能当作当前新固件指标。

本次脚本测试可验证工具输入输出；它不能证明 HLS 已重新综合、BOOT 已上板，也不能证明跨板卡通用。实际测试记录见包根目录 validation/REPORT.md。
