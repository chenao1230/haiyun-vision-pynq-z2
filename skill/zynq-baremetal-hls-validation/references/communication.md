# 裸机启动与通信定位

先画出本次数据路径：SD 帧输入、串口命令/结果，或 PC 经 TCP 上传帧。图片在电脑显示可能来自本地原图，不表示整张图片由串口返回。传输方式以当前固件为准。

|现象|先查证据|不能直接推出|
|无启动消息|启动模式、BOOT 内容、PS 日志、UART 实例/MIO、波特率、串口占用；接收端是否错过一次性启动消息|COM 可打开就表示应用已运行|
|连接但开始按钮禁用|实际 READY/FAULT 状态、协议版本、上位机状态解析、初始化阶段|一定是串口坏了|
|INVALID_RUN|命令字段、模式、板端合法组名、输入清单数量/CRC；PC 合集名称是否被直接发给仅支持单组的固件|照片损坏|
|网口亮但无结果|IP/路由/端口、应用握手、长度/CRC、帧号及收发日志|链路灯等于应用就绪|
|跑到中间停止|同一帧的读取、PL 启动/结束、后处理、结果发送、错误码|一定是算法太慢|
|画面旧、结果错位|结果帧号到原图清单映射、会话标识、场景切换状态、旧回放/当前运行来源|板卡必然算错|

最小串口测试可在初始化可到达的位置输出一次固件标识；若用户指定延时，按要求设置，不默认改成循环刷屏。单次消息测试只证明该路径可收发，仍需验证命令、返回和重复运行。

停止/重启需验证资源回收、帧边界、跟踪状态重置和下一次 READY。断电/拔卡前确认处理和文件写入完成。不要以没有串口日志时的固定等待时间代替完成证据。
