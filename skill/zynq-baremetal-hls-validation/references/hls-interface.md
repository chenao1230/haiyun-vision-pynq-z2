# PS-PL 内存接口与 HLS 验证

## 先写接口契约

使用 [契约模板](../assets/interface-contract.md)，从生成驱动、HLS pragma、地址编辑器及应用代码核对：寄存器宽度/偏移、指针参数、数据布局、shape、元素字节数、长度单位、量化比例、舍入饱和方式、tile 支持范围及完成条件。未知字段明确待查，不给默认地址。

### 直接 m_axi 访问 DDR（本项目主路径）

ARM 分配合法且生命周期足够的输入、权重和输出缓冲，把工程规定的 DDR 地址写入加速器控制寄存器。数据访问由加速器 m_axi 完成，不能直接套用 AXI DMA sendchannel/recvchannel。

在非一致性通路且启用 D-cache 时，确认 CPU 写入内容在 PL 读取前已按 BSP 语义写回；PL 写完后，CPU 读取前使旧缓存行失效。输出缓冲在启动前也需处理可能的脏行，避免后续写回覆盖 PL 结果。检查缓存行对齐、范围和相邻对象共享缓存行；具体顺序依据实际 BSP/API 和一致性路径。未确认接口时不要机械禁用全局缓存。

### 若工程确实使用 AXI DMA

另查 DMA 配置、模式、方向、长度、地址和 AXI-Stream TLAST。分配缓冲不等于发起 DMA，DMA 完成也不等于算法结果正确。此包没有 PYNQ Python DMA 实现；使用本工程的裸机驱动和协议。

### 完成与超时

按 ap_ctrl 模式或实际完成寄存器轮询，并记录超时时的状态寄存器、地址、长度、帧号。超时不能立即释放硬件可能仍访问的缓冲；先按平台流程停止/复位并确认访问结束。硬件没有可靠停止手段时保留现场，报告需要恢复步骤。

## 数值与边界测试

独立参考与 DUT 分离。整数实现对照相同量化规则的整数参考，浮点误差单独统计；不要让参考直接调用 DUT 核心函数。

覆盖实际支持的最小形状、单 tile、多 tile、尾通道、padding、stride、负值、极值/饱和，以及顶层支持的池化、上采样等模式。超出支持范围的输入应被拒绝或单独标为不支持。

对逻辑输出区前后布置保护区并验证，数值正确不代表无额外写入。输入则检查合法地址范围和实际访问：扩大输入分配、先非法读取再 mask，都不能证明内存安全。普通 C++ 参考工具可辅以 sanitizer，HLS 特有类型/综合代码另用地址检查与 RTL 仿真确认。

DUT 修改、参考测试修复、仿真 memory depth 修改分别留差异。depth 取真实合法容量，不通过扩大映射掩盖非法地址。外层 HLS 退出码 0 不足以证明成功，还要核查内部日志、错误计数与预期报告。

## 向硬件推进

C 仿真→HLS 综合→RTL 协同仿真→导出 IP→系统集成→实现→BOOT→实板逐项记录，按任务范围执行。记录各阶段源码哈希和参数；独立 IP 的 OOC 时序通过不替代完整系统时序，单算子通过不替代整网通过。
